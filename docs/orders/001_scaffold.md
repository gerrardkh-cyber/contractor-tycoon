# 발주서 001 — 프로젝트 골격

> 원문 보관. 수정 금지.

---

프로젝트 골격을 만든다. 게임 로직은 이 발주서에서 작성하지 않는다.

## 기술 스택
- Vite + TypeScript, 프레임워크 없음(순수 DOM + Canvas). Phaser 등 게임 엔진 사용 금지.
- 빌드 결과는 index.html 하나와 assets 폴더로 나와야 하고, 외부 CDN 의존 없이 오프라인에서 열려야 한다(웹게임 포털 제출 요건).
- 목표: 초기 로딩 10초 미만, 빌드 20MB 미만.

## 폴더 구조 (정확히 이대로)
CLAUDE.md, .claude/agents/, docs/{GDD.md, BALANCE.md, HANDOFF.md, orders/}, src/{core, data, ui, save}, tests/, public/
- src/core: 순수 시뮬레이션 엔진. DOM·Canvas import 금지. 입력은 상태 객체와 경과 시간(초), 출력은 새 상태.
- src/data: 프로젝트 타입·공정 단계·검사 게이트·이벤트 템플릿을 JSON으로. 코드에 숫자 하드코딩 금지.
- src/ui: core를 호출만 한다. 규칙 계산 금지.
- src/save: localStorage 저장·복원, 마지막 저장 시각 기준 오프라인 진행 계산.

## CLAUDE.md 내용
- 이 프로젝트는 영어권 웹게임 포털(CrazyGames 우선) 제출용 방치형 건설 타이쿤. 플레이어는 시공사.
- 게임 UI 텍스트는 영어. 나에게 하는 보고는 한국어 존댓말.
- 게임 규칙·숫자는 docs/GDD.md와 docs/BALANCE.md가 원본. 구현 중 규칙을 바꾸고 싶으면 바꾸지 말고 보고 후 대기.
- 발주서에 없는 기능을 추가하지 않는다. 필요하다고 판단되면 보고만.
- 실제 회사명·제품명·특정 공장 구조를 코드·데이터·아트에 넣지 않는다.
- 커밋 전 tests/ 전부 통과. 실패를 "간헐적"으로 넘기지 않고 보고.
- 각 발주서 완료 시 docs/HANDOFF.md 갱신(완료·미완·보류·다음 작업) 후 정지.

## .claude/agents/ 세 파일
1) balance-sim.md — model: sonnet. src/core만 import해 지정된 시간(예: 1h, 8h, 24h) 방치 시뮬레이션을 돌리고 시간대별 자금·현장 수·파산 여부·진행 정체 구간을 표로 보고. UI 코드 수정 금지.
2) qa-runner.md — model: sonnet. tests/ 실행. 통과 개수와 실패한 테스트 이름·트레이스 요약만 보고. 코드 수정 금지.
3) reviewer.md — model: sonnet. 변경된 파일을 읽고 GDD 위반·core에 UI 의존·data 밖 하드코딩 숫자·발주서 밖 기능 추가 여부를 보고. 코드 수정 금지.
각 파일은 name, description, tools, model 프론트매터를 갖춘다.

## docs/ 초기 내용
- GDD.md: 아래 확정 사항을 섹션으로 정리. 미확정 항목은 "TBD"로 남긴다.
  - 플레이어 = 시공사. 발주처는 NPC. RFQ → 견적 3단계(낮음/적정/높음, 낙찰 확률·마진 표시) → 낙찰 → 시공 → 검사 게이트 → 기성 → 준공(CO).
  - 프로젝트 타입은 템플릿 구조(v1 빌딩, v2 플랜트, v3 팹 슬롯만 비워둠).
  - 빌딩 공정: 층 단위 반복 파이프라인(골조 n층 완료 → 설비 n층 진입, 골조 n+1층). 건물 끝에 방수·소방·최종 검사 → CO.
  - 검사 게이트: Foundation / Structural(층별) / Rough-in MEP(층별) / Weatherproofing / Fire Marshal → Final → CO. 불합격 시 재작업 + 발주처 신뢰도 하락. 불합격 확률 = 협력업체 레벨 + 견적 마진 + 이벤트.
  - 공종 = 협력업체 카드(토목·골조·전기·배관·소방 등), 업그레이드 축.
  - 회사 층: 장비·인력·면허 등급·발주처 신뢰도는 프로젝트 간 유지. 동시 현장 v1 최대 3개. 프레스티지 = 회사 매각 후 재창업.
  - 날씨: 강우 시 타설 정지. "위험 감수 타설" 선택 존재.
  - 발주처 담당관 성향(가격/실적/기한 중시, 깐깐함)이 입찰 화면에 표시. 기성 감액 이벤트.
  - 입찰 3연속 실패 시 4번째는 지명 입찰.
  - v1.5 보류: 협력업체 부실시공 유혹(명성·하자 시스템 이후).
- BALANCE.md: 항목 이름만 표로 만들고 숫자는 전부 TBD.
- HANDOFF.md: 이 발주서 완료 상태 기록.
- orders/001_scaffold.md: 이 발주서 원문 저장.

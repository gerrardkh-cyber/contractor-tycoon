# 발주서 009 — 오프라인 정체 수정 + 아트 생성·적용(힉스필드) + 카메라

## 0. 순서
1(펀치 수정) → 2~3(슬롯·스크립트) → 4(힉스필드 생성) → 5(가져오기·적용) → 6(카메라) → 7(타이틀) → 8(정지·보고).
배포는 8에서 광희님 승인 후. 생성 이미지는 원본 PNG를 광희님이 확인하기 전까지 main에 배포하지 않는다.

## 1. 펀치 자동 처리 (규칙 변경, GDD·BALANCE 먼저 기록)
- 현장이 final 게이트에 도달하면 열린 펀치를 자동으로 처리 대기열에 넣고 순서대로 처리(건당 시간·비용 기존과 동일). 수동 "펀치 처리" 버튼은 공사 중 미리 정리하는 용도로 유지.
- 의도: 미리 안 치우면 마지막에 줄 서서 기다린다(교훈 유지), 그러나 영원히 멈추지 않는다.
- 오프라인 진행에도 동일 적용. 테스트: 펀치 4건 남긴 채 8시간 오프라인 → 준공 1건 이상, 현금 증가.
- sim으로 오프라인 복귀 시 "준공 0건 · 현금 +$0"이 나오는 시드가 남아 있는지 확인해 보고.

## 2. 아트 슬롯 재정의
- 이미지 슬롯: floors(5상태 grid/framing/framed/services/complete), foundation, roof, crane-tower, crane-jib, skyline-far, skyline-near, ground.
- sky·rain·workers·truck·inspector는 벡터 유지. ART_SLOTS.md에 "이미지 슬롯 아님" 표기.
- 슬롯에 파일이 없으면 현재 벡터로 자동 폴백.

## 3. 가져오기 스크립트 tools/import-art.py (Pillow만, python -I 실행)
- 입력: art-raw/*.png
- 마젠타(#FF00FF) 배경 키잉 → 투명, 가장자리 마젠타 번짐 제거(디스필).
- 시트 자르기: floors.png 가로 5등분, foundation-roof.png 2등분, crane.png 2등분(tower/jib). 등분 경계가 그림을 자르면 경고(투명 열 기준으로 경계 보정).
- 정규화: floors 5조각 같은 폭·높이. 위·아래 가장자리 행을 비교해 쌓았을 때 이음새가 어긋나면 경고. skyline·ground는 좌우 끝 열 비교해 타일링 이음새 경고.
- 출력: public/art/*.webp, 슬롯별 목표 폭 리사이즈, 총 용량 리포트(목표 3MB 이하).

## 4. 힉스필드 생성
- 이 컴퓨터에 이미 설정된 힉스필드 CLI를 사용(senior-story 레포에서 쓰던 것과 동일). 사용법은 CLI 도움말로 확인하고 새 패키지 설치·키 재설정 금지. 모델은 senior-story에서 검증된 nano_banana_2_lite.
- 생성 순서와 참조 규칙:
  (1) floors.png를 먼저 생성. 가로로 긴 비율(가능한 최대 가로 비율, 16:9 이상).
  (2) floors 결과가 아래 검수표를 통과하면, 그 이미지를 참조 이미지로 물려 나머지 5장을 생성. 참조 없이 생성 금지(senior-story EP035 교훈: 참조 없으면 화풍이 매번 바뀜).
- 재생성 상한: 장당 3회. 3회 안에 통과 못 하면 가장 나은 것을 남기고 사유와 함께 보고. 총 생성 횟수·소모 크레딧을 보고에 기록.
- 원본은 art-raw/에, 각 시도본은 art-raw/attempts/에 보존.

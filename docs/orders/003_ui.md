## 0. 데이터 수정 1건
normal 검사관 배율 1.05→1.12. 마진표 갱신. 다른 숫자 변경 금지.

## 1. 원칙
- src/ui는 core 호출만. 규칙 계산 금지(기존 가드 테스트 유지).
- 모든 화면 문자열은 src/ui/strings.en.ts 한 파일. 코드에 문자열 직접 쓰지 않음.
- 색·크기·도형 스타일은 src/ui/theme.ts 한 파일. 이미지 파일 사용 금지. 나중에 아트로 교체 가능하게.
- 게임 루프: requestAnimationFrame, 고정 dt(0.1초)로 core.advance 호출. 탭 비활성 시 정지, 복귀 시 오프라인 진행 적용.
- 반응형: 데스크톱 2열(현장 | 게시판+회사), 모바일 1열. 터치 대응. 가로 스크롤 금지.
- 로딩 인디케이터. 초기 로딩 10초 미만, 빌드 20MB 미만 유지.

## 2. 화면 구성
상단 바: 현금 / 부채(있을 때만) / 신뢰도(0~100 바) / 면허 등급 / 순자산 / 동시 현장 n/max.

현장 카드(슬롯 수만큼, 빈 슬롯은 "Buy slot $X"):
- 건물 캔버스: 층을 사각형으로 쌓아 표시. 층별 상태 색(대기/골조 중/골조 검사/설비 중/설비 검사/완료). 기초·외장·최종은 상하단 띠로. 현재 진행 단계에 진행 바.
- 텍스트: 타입·검사관·발주처 성향·기한 남은 시간·계약금·누적 기성·유보금.
- 정체 사유 표시(자금 부족 → 필요 금액 / 강우 → 남은 시간 / 검사 대기).
- 펀치: 열린 minor 개수 + "Clear punches" 버튼(진행 중 언제나). 비용·소요 표시. final 게이트 도달 시 0이 아니면 강조.
- pending_decision(강우): "Pour anyway (−20% inspection)" / "Wait" 두 버튼.
- 검사 결과 토스트: 통과/Major/Minor n개, 실패 시 결함명 1줄(strings 파일의 게이트별 결함 문구 3~5개 중 랜덤).
- "Abandon" 버튼: 확인 대화상자에 손실 내역(유보금 몰수·선수금 반환·신뢰도 −15) 표시 후 실행.

RFQ 게시판(3칸 + 생명줄 칸):
- 카드: 타입·층수·계약금·발주처 성향·검사관·기한·min_cash. 세 견적 버튼에 낙찰 확률과 예상 마진(%)을 표기. min_cash 미달이면 버튼 비활성 + 부족액 표시. 지명·수의계약은 Fair 단일 버튼. 생명줄은 "Take repair job" 단일 버튼, 쿨다운 표시.
- 낙찰/유찰 결과를 카드 위에 1.5초 표시 후 교체. 3연속 실패 카운터 표시.

회사 패널:
- 협력업체 5종: 레벨·다음 레벨 비용·효과(시간·검사) 표시, 업그레이드 버튼.
- 슬롯 구매, 면허 진행(준공 n/5, 순자산 x/$150K).
- 프레스티지: "Sell company (coming soon)" 비활성 표시만.

이벤트 로그: 최근 8건, 화면 하단 접이식.

오프라인 복귀 모달: 경과 시간(상한 8h 표기), 기간 중 준공·기성·검사 결과 요약.

설정: 저장 초기화(확인 2단계), 사운드 없음(v1).

## 3. 첫 30초
- 새 게임 시작 시 게시판 첫 칸은 반드시 house/lenient/지명(Fair 단일). 카드에 한 줄 힌트 3개 순차 표시: 입찰 → 골조 검사 → 기성.
- 첫 프로젝트 기초 착공까지 클릭 2회 이내.

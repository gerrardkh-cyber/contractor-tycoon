## 1. 한 줄 정의
플레이어는 **시공사(General Contractor)** 다. 발주처(NPC)의 공사를 수주하고, 협력업체를 굴려 공정을 돌리고, 검사를 통과시키고, 기성을 받아 회사를 키운다. **방치형(idle)** 진행.

## 2. 플랫폼 / 제출 요건
- 영어권 웹게임 포털, **CrazyGames 우선**. 게임 내 모든 텍스트 **영어**.
- 오프라인 실행 가능, 외부 CDN 의존 0. 초기 로딩 10초 미만, 빌드 20MB 미만.

## 2.1 단위
- 돈 `$`. 시간 **실시간 초**. **게임 내 "일" 개념 없음.**

## 3. 코어 루프

```
RFQ 게시판(3칸)
  → 견적 3단계 선택 (low / fair / high)
  → 낙찰 or 유찰
  → 시공 (층 파이프라인)
  → 검사 게이트 (통과: 기성+minor / 실패: Major 재작업)
  → 유보금·선수금 정산
  → 준공(CO) → 하자 기간 180초
```

### 3.1 RFQ 게시판
- 슬롯 **3칸**. **90초마다 가장 오래된 1칸 교체.** 낙찰·거절 시 해당 칸 즉시 교체.
- RFQ 필드: `type`, `P`(성향·검사관 보정 후), `client_trait`, `inspector`, `deadline_sec`, `advance_available`, `min_cash`
- **면허 등급 미달 타입은 게시판에 나오지 않는다.**
- **다양성**: 동시에 걸린 일반 3칸은 **`(타입 · 검사관 · 발주처 성향)` 조합이 서로 겹치지 않는다.**
  같은 타입은 **최대 2칸**까지만 걸린다. 셋 다 같은 일이면 고르는 것이 아니라 받아적는 것이기 때문이다.
  면허·신뢰도 제약으로 서로 다른 조합을 만들 수 없을 때만 제약을 풀어 칸을 채운다 — 빈 칸을 남기지는 않는다.
  게시판 첫 화면의 지명 카드(`house` · `lenient` · 가격 중시)는 이 제약보다 우선한다.
- **거절**: 일반 RFQ는 언제든 거절할 수 있고, 거절하면 그 칸이 **즉시 교체**된다.
  지명·수의계약·생명줄은 받거나 말거나이므로 거절 경로가 없다.
- **입찰 자격**: 현금이 `min_cash`(= foundation + 1개 층 structural 비용) 이상일 때만 입찰할 수 있다.
  미달이면 RFQ는 **게시판에 남되 입찰 불가**다. **기성이 들어오기 전 구간을 자기 돈으로 덮을 수 있는 일만 집으라는 뜻이다.**
- **생명줄**: **진행 가능한 현장이 없고**(현장 0이거나 전부 자금 부족 정지) **입찰 가능한 RFQ도 없으면**,
  게시판 **별도 칸(4번째)** 에 **`Repair job`** 이 하나 뜬다. 일반 3칸도, 현장 슬롯도 점유하지 않고,
  **현금·부채와 무관하게 항상 입찰 가능**하다.
  작고 지루한 수리 공사($3,000 / 60초 / 비용 0 / 검사 없음 / 하자 없음 / 낙찰 확정)다.
  **끝나면 15초 쿨다운** 동안 사라진다 — 바닥은 버티는 곳이지 눌러앉는 곳이 아니다. 건설사가 급할 때 하는 그것이고,
  **막혀 죽는 상태를 구조적으로 없애는 바닥**이다. 나중에 광고 훅("Emergency funds")이 붙을 자리이기도 하다.
- **수리 공사는 실적이 아니다.** 준공 건수에도, 신뢰도에도 반영되지 않는다.
  **연명은 되지만 성장은 안 된다** — 바닥이 탈출구가 아니라 바닥으로 남아야 하기 때문이다.

### 3.2 견적 3단계
플레이어는 **low / fair / high** 중 하나를 고른다. 각 단계는 **낙찰 확률과 마진을 화면에 표시**한다.
총공사비는 견적과 무관하게 **`0.85 × P` 고정** — 즉 낮은 견적은 마진을 깎는 선택이다.

**기준액 규칙(확정)**: 공정별 **cost 비율은 총공사비 `0.85 × P`의 배분**, **pay 비율은 낙찰금액의 배분**이다.
유보금·선수금 차감도 **pay 기준**으로 계산한다. 낙찰금액이 움직여도 공사비는 움직이지 않는다.
**기성은 각 공정이 자기 게이트를 통과할 때 자기 몫을 받는다.**

### 3.3 발주처 성향 (`client_trait`)
`price` / `track` / `schedule` 세 종류. **입찰 화면에 표시된다.**
- `price` — 싼 견적을 좋아한다.
- `track` — 신뢰도 높은 시공사를 좋아한다.
- `schedule` — 공기가 짧고, 늦으면 최종 기성을 깎는다.

### 3.4 검사관 (`inspector`)
`lenient` / `normal` / `strict`. **입찰 화면에 표시된다.**
깐깐할수록 통과율이 낮고 punch list(minor)를 많이 남기지만, **계약액이 올라간다.** 위험 대 보상.

**검사관 배율은 계약액에만 붙는다. 공사비는 배율과 무관하게 고정이다.**
깐깐한 검사관은 일을 비싸게 만드는 게 아니라 **계약을 비싸게 쳐주는 것**이다 —
늘어난 위험은 재작업과 punch list로 따로 받는다.

**`strict` 는 신뢰도가 일정 수준에 오른 뒤에야 등장한다** — 깐깐한 발주처는 실적 없는 회사에 일을 주지 않는다.
판정은 **RFQ가 만들어지는 시점**에 한 번 한다. 이미 낸 공고는 신뢰도가 떨어져도 거두지 않는다.

### 3.5 입찰 실패 구제
- **연속 낙찰 실패 3회 → 다음 RFQ 1건을 지명 입찰**(낙찰 100%, `fair` 고정).
- **신뢰도 ≥70 → 새 RFQ의 10%가 수의계약**(`fair` 고정, 낙찰 100%).
- 두 경우 모두 RFQ에 `directAward` 플래그로 표시되며, **수락은 플레이어가 한다.** 자동 수주는 아니다.
- 연속 실패 카운터는 낙찰 성공 시 0으로 리셋.

### 3.6 선수금 (advance)
- 조건은 발주처가 아니라 **플레이어 신뢰도 ≥60**.
- 낙찰 즉시 `P × 10%` 입금. 이후 **매 기성에서 10%씩 차감해 회수**한다.

### 3.7 기성 / 유보금
- 기성은 **검사 게이트 통과 시** 지급.
- **매 기성 10% 유보** → **CO 시 일괄 지급.**
- 선수금이 남아 있으면 기성에서 추가 10% 차감.

### 3.8 프로젝트 포기 (Abandon)

**언제든 포기할 수 있다.** 막힌 현장이 슬롯을 영구 점유하는 것을 막는 유일한 탈출구다.

- **유보금 전액 몰수** — 포기의 실질 비용이다.
- **선수금 미회수 잔액은 즉시 반환**한다. 현금이 모자라면 모자란 만큼 **부채로 이월**된다.
- **신뢰도 하락**, **슬롯 즉시 해제**.
- 포기한 프로젝트는 **기록만** 남는다. 준공으로 치지 않고 하자 기간도 열리지 않는다.
- **긴급 대출은 없다.** 회복은 생명줄과 다른 현장의 수입으로 한다.

### 3.8.1 현금 하한과 부채
**현금은 0 밑으로 내려가지 않는다.** 감당 못 하는 지출은 **부채**가 되고, 이후 **모든 수입의 일부가 부채 상환에 우선 배정**된다.
파산으로 게임이 끝나는 상태는 존재하지 않는다 — 느려질 뿐이다.

### 3.9 준공 (CO)
`final` 게이트 통과 시 CO. 유보금 일괄 지급, 하자보증금 납부, 신뢰도 정산, **하자 기간 180초** 진입.

## 4. 프로젝트 타입 — 템플릿 구조

프로젝트 타입은 **데이터 템플릿**이다. 코드에 타입별 분기를 박지 않는다.
각 타입은 **자기 공정 배열**을 가지며, 신규 타입은 데이터 항목 추가만으로 들어온다.

| 버전 | 타입 | 상태 |
|---|---|---|
| v1 | **Building** — `house` / `lowrise` / `midrise` | 구현 대상 |
| v2 | **Plant** (플랜트) | **슬롯만 확보** |
| v3 | **Fab** (팹) | **슬롯만 확보** |

수치는 `BALANCE.md` §2.

### 4.1 Building 공정 — 층 단위 반복 파이프라인

```
foundation
  └ 층 루프 (floors 회)
      structural n  →[게이트]→ structural 몫 기성
                     ├ mep n →[게이트]→ mep 몫 기성
                     └ 동시에 structural n+1 착수
  weatherproof
  final (fire → final) → CO
```

- `mep n` 은 `structural n` 이 **검사 통과해야** 시작한다.
- `structural n` 미통과 시 `structural n+1` 도 진입 불가.
- 층별 기성은 **두 몫으로 나뉘어 각 게이트 통과 시 각각** 지급된다 — `structural` 몫은 structural 게이트에서, `mep` 몫은 mep 게이트에서.
- **배분은 타입마다 다를 수 있다.** 층이 1개인 `house` 는 `structural` 이 통째로 한 번에 나가므로 자기 배분을 쓴다.

### 4.2 비용·정지
- 단계 **비용은 시작 시 차감.**
- 잔고 부족이면 단계를 시작하지 않고 대기 → **현장 `stalled` 표시.**

### 4.3 공기(deadline)
- 기본 = **Lv1 무실패 예상 공기 × 1.5**.
- **예외: 새 회사에 주어지는 첫 지명 RFQ 하나만 × 3.0.** 처음 한 채는 안내를 읽으며
  짓기 때문에 기한에 쫓기지 않아야 한다. 이 RFQ 만 `deadline_multiplier_override` 를
  들고 있고, 이후 모든 공고는 1.5 로 돌아간다.
- `schedule` 성향이면 추가로 × 0.8.
- 초과 시 **신뢰도 −10**, `schedule` 성향이면 **최종 기성 −10%** 추가.

## 5. 검사 게이트

| 게이트 | 단위 | 담당 협력업체 |
|---|---|---|
| `foundation` | 프로젝트 1회 | sitework |
| `structural` | **층별** | structure |
| `mep` | **층별** | electrical / plumbing / fire 평균 |
| `weatherproof` | 프로젝트 1회 | structure |
| `fire` | 프로젝트 1회 | fire |
| `final` | 프로젝트 1회 | 5종 전체 평균 |

### 5.1 통과율
```
통과율 = 검사관 기본값
       + 협력업체 레벨 보정
       − low 견적 페널티
       − risky_pour 페널티 (해당 층 structural 게이트만)
       − strict_inspector 이벤트 페널티
       → 상한·하한 클램프
```
계수는 `BALANCE.md` §5.1.

### 5.2 실패 — Major
- **재작업**: 해당 단계 시간의 일부를 다시 태우고 비용을 추가로 쓴다. 재검사.
- **통과 전 다음 단계 진입 불가.**
- 신뢰도 하락.

### 5.3 통과 — Minor (punch list)
- 통과해도 검사관 성향에 따라 **minor 결함이 남는다.** 누적된다.
- 건당 시간을 들여 **언제든 정리 가능**하고, **공정을 막지 않는다.**
- **정리 단가는 층으로 나눈다** — 게이트가 층마다 열리므로, 계약액 전체를 단가로 쓰면
  큰 건물일수록 펀치 비용이 감당 불가능해진다.
- **정리 비용은 현금으로 내지 않는다.** 공사에 청구해 두고 **CO 때 유보금에서 차감**한다.
  실제 발주처가 하는 방식이고, 푼돈이 없어 큰 공사를 버리는 일을 없앤다.
- **`final` 게이트는 열린 minor가 0일 때만 진행된다.**
- 열린 minor는 프로젝트 종료 시 신뢰도로 정산된다.
  > v1에서는 `final`이 minor 0을 강제하므로 이 감점은 **상시 0**이다. 문자 그대로 해석하는 것으로 **확정**되었다(`BALANCE.md` §0-G).

## 6. 하자 (Defect)

- CO 시 **하자보증금 납부. 반환 없음** — 준공은 공짜가 아니다.
- CO 후 **180초 하자 기간**. 이 동안 하자 발생 여부를 굴린다.
- 발생 확률은 **그 프로젝트에서 생성된 minor 총량**과 **low 견적 여부**로 올라간다.
  → 싸게 때우고 검사만 넘긴 프로젝트가 나중에 청구서를 보낸다.
- 발생 시 지출 + 신뢰도 하락. 무사 통과 시 신뢰도 상승.

## 7. 협력업체 (Subcontractors)

**공종 = 협력업체 카드.** 5종: `sitework` / `structure` / `electrical` / `plumbing` / `fire`.

- 업그레이드 축 2개: **담당 단계 시간 단축**, **담당 검사 통과율 상승.**
- 레벨업 비용은 지수 증가. 상한 Lv10.
- `mep` 단계는 electrical·plumbing·fire **세 배율의 평균**으로 굴러간다.

### 7.1 보류 — v1.5
**협력업체 부실시공 유혹** (싸게 때우고 넘어가기).
→ **명성 시스템 + 하자 시스템이 들어온 다음**에 착수. 그 전에는 구현하지 않는다.
(하자 시스템은 002에서 들어왔다. 명성 시스템이 남았다.)

## 9. 날씨 / 이벤트

이벤트는 **템플릿 JSON**이다 (`src/data/event-templates.json`).

| id | 성격 |
|---|---|
| `rain` | **선택형.** foundation·structural 정지. 선택지 **`risky_pour`** = 강행하되 해당 층 structural 검사 확률 하락 |
| `material_spike` | 다음에 시작하는 단계 비용 상승 (전역 1회성) |
| `strict_inspector` | 프로젝트 시작 시 판정. 그 프로젝트 전 검사 확률 하락 |
| `payment_delay` | 기성 입금 지연. `schedule` 성향에서 확률 2배 |
| `change_order` | 프로젝트당 1회. **발동 이후 잔여 기성만 상승(소급 없음, 공사비 불변 → 증액분은 전액 마진)** + 진행 중 단계 지연 |

### 9.1 선택형 이벤트 처리 원칙
- core는 **판단하지 않는다.** 상태에 `pending_decision` 으로 **노출만** 한다.

## 14. 안내 튜토리얼 (발주서 007)

첫 공사 1채를 실제 게임 위에서 안내한다. 별도 모드가 아니고, 실제 계약·실제 돈이다.
한 번에 한 가지만 지시하고, Next 버튼은 없다. **일어나기 전에 설명하지 않는다.**

| 단계 | 대상 | 진입 | 이탈 |
|---|---|---|---|
| T1 | 지명 RFQ 카드 | 새 회사(완공 0건·현장 0개) | 입찰 성공 |
| T2 | 현장 카드 상단 라벨 행 | T1 입찰 | **3초 경과** |
| T2현금 | 상단 바 현금 | T2 종료 | 1.5초 경과 |
| watch | (스포트라이트 없음) | T2현금 종료 | 아래 사건 |
| T3 | **검사 결과 토스트** | 첫 검사 이벤트 | 토스트 소멸 + 유예 |
| T4 | 강우 선택 버튼 행 | 첫 강우 결정 | 선택 |
| T5 | 펀치 정리 버튼 | 첫 펀치 발생 | 정리 |
| T6 | **상단 바 현금** | 준공 | 2초 경과 |
| T7 | 견적 3단계 버튼 | T6 종료 | 입찰 성공 |
| T8 | 협력업체 목록 | T7 입찰 | 3초 경과 → 종료 |

### 14.1 확정 사양 (광희님 승인, 발주서 원문과 다른 부분)
- **T2 는 "현금이 줄어드는 순간"이 아니라 3초 타이머로 끝난다.** 착공이 낙찰과 같은 틱에
  공사비를 가져가므로 기다릴 "순간"이 남지 않는다. T2 가 착공을 보여 주고 현금으로 넘긴다.
- **T6 는 현장 카드가 아니라 상단 바 현금을 비춘다.** 준공 시점에 현장 카드가 사라지므로
  가리킬 대상이 없다. 방금 들어온 돈이 더 맞는 대상이다.
- **상단 바 흐림은 T2 까지 포함**이다(현금만 제외). T2 가 끝나는 즉시 현금으로 시선을 옮기므로
  그 전에 다른 숫자를 밝혀 둘 이유가 없다.
- **T3 는 검사 결과 토스트만 잡는다.** 토스트는 `kind` 를 들고 있고 안내는 `inspection` 만
  매칭한다. 다른 토스트가 떠 있어도 T3 는 진입하지 않고, 진입 중이어도 그 토스트를 비추지 않는다.

### 14.2 숨김 규칙
T1~T6 동안: 지명 카드 외 RFQ 숨김, 회사 패널 숨김(T8 에서 해제), 로그 접힘, 빈 부지 숨김.
건너뛰기는 **안내가 도는 동안 항상 화면에 있다.** 누르면 모든 패널이 즉시 해제된다.

### 14.3 완료 기억
`localStorage` 의 `contractor-tycoon:guide`. 완료·건너뛰기 모두 `done` 으로 기록하고
다시 띄우지 않는다. 설정의 "안내 다시 보기"는 이 값을 지우며, **다음 새 회사부터** 적용된다.
